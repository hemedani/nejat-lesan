# Implement the City-Zone Backfill UI

## Objective

Add the frontend entry point for the backend's new `city_zone.backfillCityZones` act, so an admin can link existing accidents and incident reports to the city zone whose polygon contains them.

The backend now also resolves `city_zone` automatically when an accident/incident report is created. That means **new records need no frontend change** — this prompt is only about the one-off backfill for records created before the feature existed (or before a zone's geometry was imported).

Read `front/AGENTS.md` first and follow its conventions:
- Next.js App Router, React 19, TypeScript, Tailwind.
- Persian UI, RTL.
- All backend calls go through **server actions** in `src/app/actions`; never call the API directly from a client component.
- Use `pnpm`, never `npm`/`yarn`.
- **Do not** start a dev server or run a production build unless the user explicitly asks.

---

## Backend contract (already implemented — do not modify)

### Automatic write-time linking

`accident.add`, `incident_report.add` and `user.seed` now resolve the city zone from the record's `location` when no `cityZoneId` is supplied:

```ts
findCityZoneForPoint(location, cityId?)
```

- A client-supplied `cityZoneId` always wins.
- Overlapping zones resolve to the lowest `_id`.
- No match leaves the record unlinked (not an error).

Frontend consequence: **do not add client-side geo logic**, and keep `cityZoneId` optional in accident/incident forms. If an existing form already sends it, leave it alone.

### New act

```ts
// service: "main", model: "city_zone", act: "backfillCityZones"
set: {
  model?: "accident" | "incident_report" | "both"; // default "both"
  cityId?: string;                                  // optional scope; global geo index when omitted
  limit?: number;                                   // per model; backend default 5000
  dryRun?: boolean;                                 // default false
};
get: { summary: 1 };
```

Response (inside the standard Lesan envelope):

```ts
{
  success: true,
  body: {
    summary: {
      scanned: number;      // candidates read (records with no city_zone)
      matched: number;      // candidates whose point falls inside a zone
      linked: number;       // relations actually written (0 when dryRun)
      unmatched: number;    // scanned but outside every zone
      errors: number;       // COUNT, not an array
      dryRun: boolean;
      durationMs: number;
    }
  }
}
```

Important semantics:
- `limit` applies **per model**, so `model: "both"` can scan up to `2 × limit`.
- The act only fills **missing** `city_zone`; it never overwrites an existing link and never creates zone documents. It is safe to run repeatedly.
- Records outside every zone stay unlinked and are re-scanned on later runs.
- `city_zone` is a core schema and this act requires **Manager** (Ghost bypasses); no module toggle applies.

The generated declaration already exists in `src/types/declarations/selectInp.ts`:

```ts
backfillCityZones: {
  set: {
    model?: ("accident" | "incident_report" | "both");
    cityId?: string;
    limit?: number;
    dryRun?: boolean;
  };
  get: { summary: (1) };
};
```

**Do not edit this file** — it is generated from the backend. Use `ReqType["main"]["city_zone"]["backfillCityZones"]` for the action signature.

## Deliverables

### 1. Server action

Create `src/app/actions/city_zone/backfillCityZones.ts`, mirroring `seedCityZones.ts`:

```ts
"use server";
import { AppApi } from "@/services/api";
import { ReqType } from "@/types/declarations/selectInp";
import { cookies } from "next/headers";

export const backfillCityZones = async (
  details: ReqType["main"]["city_zone"]["backfillCityZones"],
) => {
  const token = (await cookies()).get("token");
  return await AppApi().send(
    {
      service: "main",
      model: "city_zone",
      act: "backfillCityZones",
      details,
    },
    { token: token?.value },
  );
};
```

Notes:
- Match the file style of the sibling actions (double quotes, `"use server"` first line).
- Do **not** add a custom URL or bypass `AppApi`.

### 2. Modal

Create `src/components/template/BackfillCityZonesModal.tsx` (`"use client"`).

Props:

```ts
interface BackfillCityZonesModalProps {
  isOpen: boolean;
  onClose: () => void;
  token?: string;
  /** Pre-fill and lock the city scope when opened from a city card. */
  cityId?: string;
  cityName?: string;
}
```

Behaviour:

1. **City scope**
   - If `cityId` + `cityName` are provided, show the city as read-only context (do not show the selector), like `SeedTrafficZonesModal` does.
   - Otherwise show an optional async city selector (`react-select/async`), reusing the pattern and `useSelectStyles` from `SeedTrafficZonesModal.tsx`. Leaving it empty means "all cities".
2. **Model scope**
   - A simple `<select>` with Persian labels:
     - `both` → «تصادفات و گزارش‌های رخداد»
     - `accident` → «فقط تصادفات»
     - `incident_report` → «فقط گزارش‌های رخداد»
   - Default: `both`.
3. **Limit**
   - Number input, default `5000`, min `1`, max `100000`, label «حداکثر رکورد در هر مدل».
   - Omit `limit` from the payload when it equals the default, or always send it — either is fine, but keep the value a number.
4. **Dry run**
   - Checkbox: «فقط پیش‌نمایش (بدون ذخیره)».
   - Default **checked** on first open for safety; the submit button label switches between «پیش‌نمایش» and «اجرای همگام‌سازی».
5. **Submit**
   - Call the server action with `{ set: { model, cityId?, limit, dryRun }, get: { summary: 1 } }`.
   - While running: disable every control and show the same spinner pattern used by `SeedTrafficZonesModal`.
   - On `result.success && result.body?.summary`:
     - Store the summary and render a result panel (see copy below).
     - Call `router.refresh()` only when `linked > 0` and `dryRun === false`.
     - Show a success toast; for dry run, an info/success toast saying nothing was written.
   - On failure: `ToastNotify("error", \`خطا در همگام‌سازی مناطق: ${result.body?.message || "خطای نامشخص"}\`)`.
6. **Reset**
   - On close, reset `summary`, `isProcessing`, and any editable fields to defaults.
7. **Accessibility / UX**
   - Use `useScrollLock(isOpen)`.
   - RTL labels and text.
   - Close button disabled while processing.
   - Keep the existing visual language: `bg-surface`, `border-line`, `text-fg`, `text-fg-muted`, `bg-brand`, `text-on-brand`, `bg-success-soft`, `border-warning-border`, `z-[2000]`, `max-h-[90vh] overflow-y-auto`.

Result panel content (Persian):

```text
- خوانده‌شده: {scanned}
- یافت‌شده در منطقه: {matched}
- پیوند داده‌شده: {linked}
- خارج از منطقه: {unmatched}
- خطا: {errors}
- مدت اجرا: {durationMs} میلی‌ثانیه
```

Show a prominent «پیش‌نمایش — هیچ تغییری ذخیره نشد» banner when `dryRun` is true. When `unmatched > 0`, add a muted note that records outside every zone remain unlinked and can be checked after importing zones.

Use `formatNumber` from `@/utils/formatters` for Persian digits if it fits the surrounding components; otherwise plain numbers are acceptable.
