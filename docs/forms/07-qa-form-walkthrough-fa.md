# ۰۷ — بررسی فرم تصادف QA

نمونهٔ مرجع تیم کیفیت، `qa_docs/QA_AR/Accident_Report_App.html` است با ۷۳۹ خط
جاوااسکریپت دست‌نویس. این نمونه **به‌طور کامل** به‌صورت یک تعریف بازتولید شد — و
هنوز هم هست، جز آنجا که ترتیبِ جدیدِ مشتری فرم را جلوتر برده است:

```
shared/form-engine/src/qa-accident-form.ts        خودِ تعریف
mobile/src/domain/qa-accident-form.ts              شیم باز-اکسپورت به همان فایل
mobile/src/domain/qa-accident-form.test.ts         ۴۸ تست پذیرش
```

تعریف در موتورِ مشترک زندگی می‌کند، نه در درختِ منبعِ یک اپ، چون هم تستِ پذیرشِ
موتور است و هم فرمِ تصادفی‌ای که بک‌اند برای یک سازمان دمو فعال می‌کند، در حالی که
موبایل آن را رندر می‌کند. مسیرِ موبایل حالا فقط یک باز-اکسپورتِ تک‌خطی است، پس یک
artefact داریم، نه دو تا.

این سند هر رفتار نمونهٔ اصلی را به سازوکاری که اکنون آن را پیاده‌سازی می‌کند نگاشت
می‌دهد. آن جدول معیار پذیرش است: **هر سطر اعلانی است، بدون هیچ کد اجرایی پشت
آن.** رفتاری که برای بیان شدن به کد نیاز داشته باشد یعنی موتور به اندازهٔ کافی
عمومی نیست، و آن شکاف متعلق به موتور است — نه به یک تعریف خاص.

## کنار هم

| نمونهٔ اصلی | سازوکار | کجا |
| ------------ | ------- | --- |
| ویزارد ۸ مرحله‌ای با نوار کناری | `pages[]` | ۸ صفحه |
| گیت `hasDamage === 'بله'` | `visibleWhen` روی گروه تکرارشونده | `damages` |
| `plateType` ← ۴ زیرفرم متفاوت | `plateVariants` انتخاب‌شده با شرط | `plate_national`، `plate_motorcycle`، `plate_free`، موقت |
| وسیلهٔ سنگین ← انتخاب نوع بار | `visibleWhen` + `requiredWhen` | `cargo` |
| تودرتوی `vehicles[].passengers[]` | `RepeatableNode` تودرتو | `vehicles → passengers` |
| `errors()` جلوگیری می‌کند، `warnings()` هشدار می‌دهد | `requiredWhen` در برابر `validation.warnings` | در سراسر فرم |
| تغییر نوع پلاک، بخش‌های پلاک را پاک می‌کند | `clearOnChange` | `plateType` |
| دست‌کم یک وسیله | `minItems: 1` | `vehicles` |
| گزینه‌های رنگ‌بندی‌شدهٔ خطر | `OptionItem.tone` | `severity`، `vehicleType`، `cargo` |
| راننده متصل به وسیله | گروه تکرارشونده با `maxItems: 1` | `vehicles → driver` |
| برخورد با وسیله نقلیه با تنها یک وسیله در پرونده | `count` زیر `not` | `collision` |
| تصادف همین حالا رخ داده است | `defaultSource: "now"` | `date_of_accident`، `time_of_accident` |

سه رفتارِ نمونهٔ اصلی **حذف شده‌اند، نه نگاشت**: چون آنچه به آن خدمت می‌کردند رفته
یا هرگز عمومی نبود:

- `emergency ← پشتیبانی پیشنهادی` — به مرکز کنترلی خوراک می‌داد که هنوز عملیاتی
  نیست. با آن `traffic`، `emergency`، `emergencyNotes`، `support` و `supportNotes`
  هم رفتند، و همچنین هشدار جرثقیل که `support` را می‌خواند.
- فهرست‌های گزینهٔ `reference` در نمونهٔ اصلی — هر فهرستی در این فرم literal است،
  پس بدون هیچ شبکه‌ای رندر می‌شود. فرمی که اپ به‌عنوان جانشینِ آفلاینِ خود حمل
  می‌کند نمی‌تواند منتظر سرور بماند تا گزینه‌های خودش را بشناسد.

## تعویض پلاک — سخت‌ترین الزام

تابع `plateFields` نمونهٔ اصلی بر اساس `plateType` بین چهار شکل کاملاً متفاوت
جابه‌جا می‌شود. اینجا هر شکل، فیلد خودش است که با شرط کنترل می‌شود:

```
plate_national      ملی              → ۲ رقم / حرف / ۳ رقم / ۲ رقم
plate_motorcycle    موتورسیکلت        → ۳ رقم / ۵ رقم
plate_free          منطقه آزاد         → کد منطقه / ۵ رقم
plate_temporary_*   گذر موقت / خاص     → شناسه / شماره
```

تعویض نوع، بقیه را پاک می‌کند، چون شکل‌ها با هم سازگار نیستند:

```jsonc
{
  "key": "plateType",
  "clearOnChange": ["plate_national", "plate_motorcycle", "plate_free"]
}
```

## نوع بار فقط برای وسایل سنگین

تابع کمکی `heavy(v)` در نمونهٔ اصلی:

```ts
['وانت بار','مینی‌بوس','اتوبوس','کامیونت','کامیون','تریلی','تانکر حمل مواد خطرناک','خودروی آتش‌نشانی']
```

به یک قاعدهٔ اعلانی تبدیل می‌شود:

```jsonc
{ "op": "in", "path": "vehicleType", "value": [ … ] }
```

با همان فهرست، هم روی `visibleWhen` و هم روی `requiredWhen`.

## هشدارهای بین‌ردیفی

دو مورد از `warnings()` نمونهٔ اصلی باقی مانده‌اند.

**شدت خسارتی با وجود مصدوم در پرونده:**

```jsonc
{ "op": "and", "rules": [
  { "op": "eq", "path": "severity", "value": "خسارتی" },
  { "op": "or", "rules": [
    { "op": "anyIn", "path": "vehicles[].passengers[].health", "value": ["مصدوم", "فوتی در صحنه"] },
    { "op": "anyIn", "path": "pedestrians[].health",           "value": ["مصدوم", "فوتی در صحنه"] },
    { "op": "anyIn", "path": "vehicles[].driver.presence",     "value": ["در صحنه فوت شده", "به بیمارستان منتقل شده"] }
  ]}
]}
```

این همان بررسی‌ای است که اگر `anyIn` وجود نداشت، ما را ناچار به زبان عبارتی
می‌کرد. سه خط JSON است.

راننده از `driver_presence` خوانده می‌شود، نه از یک فیلد سلامت، چون فرم دیگر
سلامتِ راننده را نمی‌پرسد — آن دو یکدیگر را تکرار می‌کردند و می‌توانستند ناسازگار
شوند. `driver_presence` همان فیلدی است که واقعاً می‌داند، و تنها فردی است که هر
وسیله همیشه دارد؛ پس حذف آن بررسی را نسبت به مصدومِ راننده کور می‌کرد.
«متواری شده است» یعنی راننده رفته، نه اینکه آسیب دیده، و عمداً کنار گذاشته شده
است.

**برخورد با وسیله نقلیه با تنها یک وسیله در پرونده** — محدود به پاسخ، نه به یک
ردیف:

```jsonc
{ "op": "and", "rules": [
  { "op": "eq",   "path": "collision", "value": "برخورد با وسیله نقلیه" },
  { "op": "not", "rule": { "op": "count", "path": "vehicles", "gte": 2 } }
]}
```

«کمتر از دو وسیله» به‌صورت نقیضِ `gte: 2` نوشته می‌شود، چون `count` عملگر `lt`
ندارد. این هشدار پیش‌تر `count >= 2` **و** `not (count >= 2)` را با هم داشت — یک
تناقض، که برای هر پاسخ ممکن نادرست است، پس هرگز — با هر طریقی که گزارش پر می‌شد —
نمایش داده نشده بود. به
[تغییرات طراحی](#تغییرات-طراحی-حین-بازتولید) نگاه کنید.

**مدرک ناقص** — نمونهٔ اصلی وسایل و آسیب‌های بدون عکس را علامت می‌زند.

## مقادیر آغازین — «امروز» بدون یک مقدار ثابت

`defaultValue` یک مقدار ثابت است که داخل تعریف حمل می‌شود. یک تعریف یک بار نوشته
می‌شود و هر گزارشی که تا همیشه علیه آن ثبت شود به آن پاسخ می‌دهد، پس نمی‌تواند
بگوید «امروز». بنابراین فیلدی که باید از لحظهٔ کنونی شروع کند، به‌جای مقدار، یک
**منبع** را نام می‌برد:

```jsonc
{ "key": "date_of_accident", "type": "date", "defaultSource": "now" }
{ "key": "time_of_accident", "type": "time", "defaultSource": "now" }
```

`seedDefaultAnswers(definition, answers, now)` آن را هنگام باز شدن فرم در برابر
ساعتِ کلاینت حل می‌کند — `date` تاریخ امروز، `time` ساعت کنونی، `datetime` هر دو
را، و در همان قالبِ بخش‌های محلی که خودِ انتخابگر می‌نویسد (هرگز
`toISOString()`، که روز را برای هر کسی شرق یا غرب UTC جابه‌جا می‌کند). فیلدِ
غیرزمانی آن را نادیده می‌گیرد، به‌جای اینکه یک timestamp در یک جعبهٔ متنی بنویسد.

کاشتن، افزایشی است و **آخر از همه** اجرا می‌شود: پاسخی که از پیش‌نویس بازیابی شده
همیشه برنده است، پس انتخابِ خودِ مأمور هرگز با یک پیش‌فرض بازنویسی نمی‌شود. این
مأموری است در کنار جاده که چیزی را توصیف می‌کند که همین حالا رخ داده، پس حالتِ
رایج نباید اصلاً به باز کردن انتخابگر نیاز داشته باشد — اما این یک پیش‌فرض است،
نه یک واقعیت. به [۰۲ طرح‌وارهٔ تعریف](./02-definition-schema-fa.md) نگاه کنید.

## نگاشت‌ها — چرا نمودارها کار می‌کنند

یک فیلد روی یک رابطهٔ typed در `accident` نگاشت می‌شود:

```jsonc
{ "key": "date_of_accident", "binding": { "kind": "pure", "path": "date_of_accident" } }
```

`severity`، `collision` و `lighting` عمداً **نگاشت نشده‌اند**. نگاشت `relation` یک
شناسهٔ رکورد می‌نویسد، و این‌ها انتخاب‌های literal هستند که پاسخشان متنِ «خسارتی»
است — نگاشتِ آن‌ها payloadی می‌ساخت که بک‌اند رد می‌کرد
(`typeId: objectIdValidation`) و هر ارسال شکست می‌خورد. پاسخ‌هایشان هنوز ذخیره
می‌شوند، در `dynamic_answers`، و هر ۳۴ اکشن تحلیل و نمودار موجود همان فیلدهایی را
می‌خوانند که همیشه می‌خواندند.

## تغییرات طراحی حین بازتولید

بازتولید نمونه، دو مشکل ساختاری را آشکار کرد؛ سومی بعدها سر باز کرد.

**رانندگان فهرستی جدا بودند.** نمونهٔ اصلی وسایل و رانندگان را در برگه‌های جدا با
کلید اندیس نگه می‌دارد، که می‌تواند از هم جدا بیفتد — راننده می‌تواند به اشتباه به
وسیلهٔ دیگری بچسبد، و دو فهرست کلیدهای تکراری دارند که هر شرطی را که آن‌ها را
نام ببرد می‌شکند. راننده به یک گروه تکرارشوندهٔ `maxItems: 1` درون هر وسیله تبدیل
شد. یک ردیف، یک راننده، بدون کلید تکراری.

**گیت آسیب دایره‌ای بود.** `hasDamage` روی صفحه‌ای بود که خودش گیت می‌کرد — تنها
پس از `hasDamage === 'بله'` ظاهر می‌شود، پس پاسخ‌دادن به پرسشی که خودش در را باز
می‌کند ناممکن بود. حالا صفحه بی‌قید‌و‌شرط است و پاسخ فقط فهرست `damages` را گیت
می‌کند: «بله» همان‌جا «افزودن آسیب» را آشکار می‌کند، «خیر» صفحه را خالی ثبت می‌کند.
`minItems: 1` روی آن فهرست همان چیزی است که «بله» را به «دست‌کم یکی ثبت کن»
تبدیل می‌کند؛ به `requiredWhen` نیازی نیست، چون گرهٔ ناپیدا هرگز الزامی نیست و
اعتبارسنج یکسره از آن می‌گذرد.

**هشداری که هرگز نمی‌توانست فعال شود.** هشدار برخورد با وسیله نقلیه
`count >= 2` **و** `not (count >= 2)` را می‌خواند. پیامِ خودش قصد را می‌گوید
(«برای برخورد با وسیله نقلیه بیش از یک وسیله لازم است»)، پس نیمهٔ زائد حذف شد و
اکنون دو تست هر دو جهت را تثبیت می‌کنند.

## اجرای تست‌های پذیرش

```bash
cd mobile && npx vitest run src/domain/qa-accident-form.test.ts
```

۴۸ تست پوشش می‌دهد: ساختار هشت‌صفحه‌ای، کلیدهای یکتا، نبود نوع فیلد
پشتیبانی‌نشده، گروه‌های تکرارشوندهٔ تودرتو، نگاشت‌ها، هر قاعدهٔ نمایش شرطی، هر
تعویض پلاک، گیت نوع بار، رنگ‌بندی، هر هشدار که فعال و پاک می‌شود، پاک‌سازی‌های
وابسته، `minItems`، مقادیر آغازین، و اعتبارسنجی یک گزارش کامل، صفحه به صفحه.

اگر هرکدام از این‌ها برای بیان شدن به کد نیاز داشته باشد، یعنی موتور به اندازهٔ
کافی عمومی نیست — و دقیقاً به همین دلیل این فایل یک تست است، نه دادهٔ اولیه.
